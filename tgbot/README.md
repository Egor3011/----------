# Telegram-бот записи к психологу

Реализован по `info.md`: главное меню, цены, отзывы, выбор даты и времени, необязательные комментарий и телефон, подтверждение заявки администратором, просмотр записей и управление перерывами.

## Запуск локально

Нужен Python 3.10 или новее. Из корня проекта:

```bash
python3 -m venv tgbot/.venv
tgbot/.venv/bin/python -m pip install -r tgbot/requirements.txt
cp tgbot/.env.example tgbot/.env
```

Заполните `tgbot/.env`:

- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather).
- `ADMIN_ID` — числовой Telegram ID администратора, не username. Его можно узнать у [@userinfobot](https://t.me/userinfobot), а после запуска бота — командой `/id`.
- `BOT_TIMEZONE` — часовой пояс расписания; по умолчанию `Europe/Moscow`.
- `DATABASE_PATH` — путь к SQLite. Относительный путь считается от папки `tgbot`; по умолчанию `data/bot.sqlite3`.

```bash
tgbot/.venv/bin/python tgbot/main.py
```

Администратор должен открыть личный чат с ботом и отправить `/start`, чтобы бот мог присылать ему заявки. Главное меню покажет кнопку «Админ-панель» только этому пользователю. Также доступна команда `/admin`. Бот работает в личных чатах через long polling; публичный сервер и HTTPS не нужны. Запускайте один экземпляр бота на токен и базу.

Токен из прежней версии `main.py` удалён из исходников. Он находился в репозитории: перед запуском отзовите его через BotFather и укажите новый в `.env`. Файл `.env` и база не попадают в Git.

## Запуск через Docker Compose

После заполнения `tgbot/.env` из корня проекта:

```bash
docker compose --profile bot up -d --build tgbot
docker compose logs -f tgbot
```

База хранится в именованном томе `bot-data` и переживает пересоздание контейнера. Не удаляйте этот том, если нужно сохранить записи. Профиль `bot` позволяет запускать сайт отдельно привычной командой `docker compose up -d --build`. Для остановки бота: `docker compose stop tgbot`.

## Правила расписания

- Доступны сегодняшний день и даты не далее 14 календарных дней от него, с учётом часового пояса бота.
- Понедельник–суббота, сеансы по 60 минут. Начало с 08:00 до 17:00 включительно: последний сеанс заканчивается в 18:00. Воскресенье исключено. Прошедшее время не предлагается.
- Только отправленная заявка резервирует час. Пока клиент вводит данные, час может занять другой клиент; перед отправкой доступность проверяется повторно.
- Ожидающая решения заявка и подтверждённая запись блокируют час. Транзакции SQLite и уникальный индекс защищают от одновременной записи на один час.
- Администратор подтверждает заявку или отменяет её. Отменённый час снова доступен. Подтверждённую встречу можно отменить через список записей. Повторное нажатие не меняет уже принятое решение и не создаёт дубликат заявки.
- Перерывы задаются кнопками с точностью до часа; можно закрыть весь день, выбрав 08:00–18:00. Перерыв не может пересечь ожидающую заявку, подтверждённую запись или другой перерыв. Перерывы можно удалить.
- В списке администратора есть пагинация, карточки клиентов и просроченные необработанные заявки. Подтвердить встречу в прошлом нельзя; её можно отменить.
- Встречи вне обычного времени согласуются через ссылку на менеджера @h010dok с доплатой. Автоматическая запись вне расписания не предусмотрена инструкцией.
- Два пакета **по 10 встреч** сохранены буквально из инструкции: по 1500 ₽ и по 900 ₽ за встречу. Условия их различия уточняются у администратора. Первая запись сопровождается предложением скидки 50%; бот не принимает оплату и не рассчитывает право клиента на скидку.

Расписание, заявки, комментарии, телефоны, решения и очередь уведомлений сохраняются в SQLite. Незавершённая форма клиента хранится в памяти; после перезапуска нужно открыть `/start`. Уже отправленные заявки сохраняются.

Уведомления отправляет фоновая очередь. При ошибке Telegram повторная попытка выполняется с растущей задержкой до одного часа; очередь сохраняется при перезапуске. Если пользователь заблокировал бота, уведомление останется в очереди до восстановления доступа. В редком случае остановки процесса сразу после отправки, но до записи результата в БД, уведомление может прийти повторно; само бронирование не дублируется.

Часовой пояс после появления записей меняйте только с учётом того, что в базе хранятся местные даты и часы. Для резервного копирования работающей SQLite используйте её backup API; простое копирование только `.sqlite3` во время работы может не включить WAL. Контакты и комментарии доступны администратору, а также владельцу файлов базы.

## Проверка

```bash
tgbot/.venv/bin/python -m unittest discover -s tgbot/tests -v
```

Тесты без обращения к Telegram проверяют календарь, границы рабочего дня, воскресенья, конкурирующие заявки и перерывы, сохранение после перезапуска, роли, переходы формы, контакты, экранирование HTML, решения администратора и повторную доставку уведомлений.

Для проверки в Telegram: отправьте `/start` с клиентского аккаунта, выберите дату и время, отправьте заявку, подтвердите её с аккаунта `ADMIN_ID` и проверьте сообщение клиенту. Второму клиенту занятый час не должен предлагаться. Затем добавьте и удалите перерыв в админ-панели.

Используется [pyTelegramBotAPI — официальная документация](https://pytba.readthedocs.io/en/latest/sync_version/index.html).
